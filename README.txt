  Core5 Operating System

This repository holds the build system alongside
all of the source code of the Core5 Boot Loader,
Kernel, all of the necessary tools needed to build
the project and many development and usage utilities.

    Boot Loader Architecture

The Boot Loader architecture is split into two stages
when booting all supported media (floppy disks and
hard disks). The first stage, referred to internally as
the stage 1 or stage 1 Boot Loader, is a single binary
assembled with flat assembler g from `Boot Loader/Boot
Sector.asm`. The resulting binary contains both of the
boot paths and decides which to invoke at runtime by
consulting the boot drive number passed in by the BIOS.

On hard disk drives (HDDs) the stage 1 uses the Extended
Read IBM/Microsoft INT 13h BIOS extension to read the
second stage Boot Loader, otherwise referred to as stage 2,
from the "gap" before the beginning of the lowest-addressed
partition.

On floppy disks, the stage 1 uses the standard Read Sectors
into Memory INT 13h BIOS function to load the FAT12 filesystem
information into memory, walk the filesystem's root directory,
locate a file called BOOT.BIN--the second stage Boot Loader--in
it and load it into memory.

On failure of either path, the stage 1 simply outputs "Boot
error", prompting the user to press any key to reboot. Due
to size constraints, no further information can be given
without making the error output cryptic to the end user.

The stage 1 is also heavily size constrained since the same
binary must still contain the BIOS Parameter Block and the
Extended Boot Record as well as the MBR metadata from offset
0x1B8 onwards, regardless of the medium it is installed to.

    Tools

Tools are host programs that are assembled on the build
machine and perform some action related to the build
process of Core5.

        Install FAT Boot File

This tool is responsible for installing the stage 2
to a disk image currently being generated by the build
system. It accepts only two arguments, the disk image
(already containing the filesystem/partition table)
and the stage 2 binary image, referred to as the source
file image internally in the source code. The tool
autodetects whether the passed-in image is a FAT12-formatted
floppy disk image, or an MBR-partitioned hard disk image
with at least one FAT32-like partition.

Based on this it employs the appropriate mechanism for
installing the stage 2 to the disk image.

For floppy disk images, it simply walks the root directory
directory entries, looking for a suitable (empty or deleted)
entry. Once it is found and space constraints are verified,
space for the stage 2 is allocated in the data area, a FAT
cluster chain is created and linked to the directory entry.

Time-related metadata is currently stubbed, with ambitions
for proper implementation of transfer thereof.

For hard disk images, the tool instead scans for the
lowest-addressed partition, verifies that there is a
large enough "gap" for the stage 2 to be placed there
and subsequently copies the source file into the "gap".

    Building

Core5 can be built on GNU/Linux (also known as SystemD/Linux)
or (in the future) on Core5 itself. On GNU/Linux the following
programs are required to be installed on the build machine:

 GNU Make, Bash, mtools, sfdisk, coreutils and git.
Flat assembler g (fasmg) is vendored as a git submodule and must
be fetched.

QEMU and/or Bochs must be available in order to run the disk images
in said emulators, with GDB, socat and awk required in order to debug
disk images with QEMU and Bochs built with it's internal debugger required
for debugging images with Bochs.

On non-x86 hosts, a multiarch gdb and cross objcopy supporting elf32-i386
must be used in order to properly debug with QEMU.

Invoking the Make default rule will build the Boot Loader along with
the two supported disk images at `Work/Images/`.
